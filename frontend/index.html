How it works

From a question to something you can rely on.

  1. Ask

    State one research question and choose a mode: explore, compare, investigate, literature review or brief.

  2. Gather

    Atlas retrieves and ranks sources by relevance and credibility, then reads them.

  3. Verify

    Claims are extracted, traced to their sources and cross-checked for consistency and confidence.

  4. Use

    The case is filed in your Library, where the Playground, AtlasBench and Ask Atlas can build on it.

Features

Four jobs, one account.

Research with evidence you can inspect, evaluate the AI systems you rely on, build workflows that run the same way every time, and control which models execute.

Research with traceable evidence

Ask a question and get a report whose claims each point back to the passage that supports them, scored and labelled.

  • Claims are cross-checked against each other and the confidence is stated
  • A knowledge map connects claims, evidence, contradictions and challenges
  • Cases live in a Library you can search by meaning, annotate and export

Evaluate AI systems

Judge models on evidence, not impressions. Compare answers side by side, then score configurations against a frozen task.

  • AI Playground. Put one question to up to three models, with the same retrieved evidence beside each answer, plus tokens and estimated cost.
  • AtlasBench. Six metrics, from claim correctness to contradiction handling, on frozen tasks so runs can be compared and reproduced.
Try the Playground

Build workflows

Save a bounded workflow from a template, run it on any text, and read what every step did.

  • Only steps the server can execute deterministically are accepted
  • Runs carry an idempotency key, so a retry does not repeat work
  • Full run history with step-by-step outcomes

Control model execution

Decide how models are chosen, preview the decision, and audit what actually ran, what it cost and when a fallback fired.

  • Explicit or autopilot model selection, saved as your policy
  • Preview a routing decision without calling a model
  • Every call shown as requested model → actual model

Security and trust

What Atlas does, stated plainly.

These describe how the software behaves. They are not certifications, and deployment settings can change some of them.

  • PasswordsHashed with Argon2id. Hashes from an older scheme are still accepted and upgraded at your next sign-in.
  • SessionsSigned access tokens that expire; seven days by default, set by whoever runs the deployment.
  • Abuse limitsSign-in, sign-up and password-reset requests are rate-limited per client address.
  • Password resetSingle-use reset tokens that expire. The request never reveals whether an email has an account.
  • Your dataCases, conversations, workflows, benchmark runs and routing policies belong to your account and are not listed for other accounts.
  • No silent swapsWhen a fallback is enabled, every call is shown as the model you asked for and the model that answered.

What this page does not claim. No compliance certification, no uptime guarantee and no data-residency promise is made here. Those depend on who runs your deployment; ask them.

FAQ

Straight answers.

What is Atlas for?

Atlas is a workspace for AI work you need to be able to check: research with sources and verified claims, side-by-side model comparison, repeatable benchmarks, simple automations and control over which models run.

Does a verification score mean a claim is true?

No. It measures how consistently the evidence supports a claim and how confident the check is. Partial or weak support is labelled as such, with the sources beside it so you can judge.

Do I need my own API keys?

Atlas uses the search and model providers configured by whoever runs the deployment. If you are signing in to someone else’s deployment, you do not bring keys.

Where is my work stored?

In the database of the deployment you sign in to, attached to your account. You can delete cases, conversations and workflows from inside the app.

Can I reset a forgotten password?

You can request a reset. Delivery depends on the person running the deployment having configured email; if no email arrives, ask them to reset it for you.

Where is Runtime & Control?

It is its own area in the workspace. Policies, routing previews and the usage ledger live there, and it shares its backend with AtlasBench.

Is there an API or a mobile app?

Atlas is a web app. The backend exposes an HTTP API used by this interface; no separate mobile app or public API programme is offered on this site.
